# Git 工作台推荐操作回归报告

- 日期：2026-09-09
- 分类：Git 可视化、远程工作区、移动端工作流效率
- 负责人结论：本轮实现完成，待本地/远端 CI 继续验证。

## 主动发现的问题

Git 工作台已经具备状态概览、下一步建议、按文件审查、暂存、提交、快进拉取、普通推送、分支和 stash
管理。但在手机上，文字建议与实际动作仍然分离：用户看完“下一步建议”后，还要在一排横向滚动按钮中找
对应动作。

这个问题不会导致 Git 功能错误，但会增加 AI 修改后的验证成本，属于用户体验和移动端效率缺口。

## 改动范围

- 在 Git 工作台概览页的“下一步建议”下方增加“推荐操作”主按钮。
- 推荐按钮根据当前仓库状态映射到已有安全流程：
  - 有未暂存/混合修改：按文件审查。
  - 只有已暂存修改：打开提交确认。
  - 工作树干净且落后上游：打开快进拉取确认。
  - 工作树干净且领先上游：打开普通推送确认。
  - 无上游：打开新建本地分支确认。
  - 游离 HEAD：打开分支列表。
  - 工作树干净且同步：打开提交记录只读列表。

## 安全边界

- 推荐按钮不新增 Git 命令。
- 推荐按钮不会直接提交、拉取、推送、删除、stash 或切换分支。
- 写操作仍复用既有确认弹窗和命令层保护。
- 不提供 force push、force delete、hard reset、stash clear 或远端分支删除。
- 不读取或保存远端仓库秘密。

## 验收标准

- 下一步建议能被首屏主按钮承接，不要求用户在横向按钮长条中自行查找动作。
- 各状态下推荐动作符合最小风险原则。
- 推荐按钮的无障碍描述说明操作边界。
- 原有 Git 操作入口仍保留，专家用户可继续按需选择。
