# AI 会话中心核心操作可发现性验收

## 场景与问题

- 目标旅程是开发者已确认远程工作区后，选择 Claude Code 或 Codex CLI 的“新建”或“历史选择”。
- 旧页面把两个新建操作放在首屏，但 Claude/Codex 历史入口落在各自长说明之后。用户要继续已有工作时，不能在同一个决策区域比较四种操作。
- Claude 运行在共享账号时，不能为了压缩界面而隐去“历史只打开原生选择器、不自动恢复、确认归属”的安全边界。

## 体验修复

1. 将 Claude/Codex 的新建与历史重组为首屏 2×2 操作区，短标签分别为“新建 Claude / Claude 历史 / 新建 Codex / Codex 历史”。
2. 新建使用成功色，历史使用中性色，既避免把历史误读为默认路径，也避免把它藏在解释性卡片之后。
3. 每个按钮保留完整无障碍描述：所有新建均为 SSH-only、不恢复历史、不自动进入 tmux；Claude 历史额外提示共享账号会话归属。实现未读取 AI 私有历史，历史入口只运行 CLI 原生 picker。
