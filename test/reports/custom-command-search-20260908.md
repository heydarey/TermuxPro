# 快捷指令移动端筛选验收记录

## 选题与体验判断

- 增值服务分类：自定义快捷指令、移动端工作流效率、上下文工具箱。
- 真实旅程：开发者为 Git、tmux、Codex/Claude、构建与发布积累多条当前工作区指令后，原列表只能上下
  滚动寻找；手机软键盘场景下，记住分组和手动翻找的成本过高。
- 取舍：不把低频指令重新堆回首页；筛选留在“工具箱 → 快捷指令”页，只改变本地页面显示，避免引入云
  同步、远端检索或任何新的命令执行能力。

## 交互设计

1. 当当前工作区达到 4 条指令时，在“模板 / 新建”之后提供明确的“筛选当前工作区指令”输入框，可按
   名称、场景、命令或工作目录匹配；少于 4 条时隐藏该输入，优先让首条可执行动作留在首屏。
2. 输入时实时显示“已显示 / 总数”，结果为零时说明可检查哪些关键词；有输入时出现独立的“清除”按钮，
   避免手机用户只能长按或逐字删除。
3. 筛选后仍保留场景标题；管理菜单中的上移、下移使用原始存储位置，筛选不会悄然重排、删除、停用或执行
   指令。
4. 无有效工作区时禁用筛选，且仍显示既有的安全恢复说明；跨工作区数据不会被回退或混合。
5. 截图审计显示原先的通用说明在 200% 字体下占据大量首屏空间；现改为“保存当前工作区常用命令；运行前
   始终核对目标。”并限制最多三行，不通过缩小字体牺牲可读性来换取空间。

## 截图审计证据

- 审计来源：本轮前一提交的 GitHub Emulator UI artifact `termuxpro-emulator-ui-236`，`360dp`、深色、简体中文。
- 默认字体：`custom-commands-default.png` 显示两条指令时首条可执行卡片已位于首屏下半部；常驻搜索会进一步
  推低它，因此筛选改为达到 4 条指令才显示。
- 200% 字体：`custom-commands-font200.png` 显示原通用说明扩展为约 7 行，压低“执行目标”和首条快捷指令；
  本轮收敛为单句、最多三行。
- 可见性与无障碍边界：截图证明深色背景、文字对比和布局没有被裁切；不能单凭截图证明 TalkBack 阅读顺序、
  输入法焦点和 OEM 字体渲染，已保留给 Robolectric/模拟器运行时回归。
