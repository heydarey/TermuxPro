# Git 工作台修改审查优先级验收

## 场景与问题

- 开发者在远程项目中看到“有未提交文件”后，首要任务是按文件核对或查看 Diff，再决定暂存、提交、切换分支或 stash。
- 原概览把所有操作塞在横向分支工具条中；在 360dp 和尤其 200% 字体下，页面给出的“先点按文件核对”建议与实际入口相距很远。
- 初次 UI fixture 使用 `invalid:0` 伪目标，虽然不连接网络，却会使验收截图误导读者，不能作为产品可读性证据。

## 体验修复

1. 当 Git 状态含有可审查文件时，在同步状态之后显示“先审查当前修改”卡片，提供全宽“按文件审查”和“查看完整 Diff”。
2. 没有实际文件改动时隐藏该卡片，不以禁用按钮占据首屏；分支、同步、暂存和提交功能保持在原有安全语义中。
3. 模拟器 fixture 改为有效 `hdr@192.168.1.153:22 · ~/project` 目标与真实 `status --porcelain -z` 风格数据；不发起 SSH，不访问真实服务器或 tmux。

- 200% 字体截图中 Git 顶栏标题与“刷新”视觉间距过小，应单独审计标题缩放和操作区最小间距；本轮不以缩小字体或删除刷新动作掩盖问题。
