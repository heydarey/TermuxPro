# Git 远端同步动作目标上下文回归报告（2026-09-19）

## 背景

Git 工作台已把分支和暂存类状态变更动作补齐当前目标上下文。继续从开发者真实手机使用场景巡检后发现，快进拉取和普通推送确认页虽然说明了 `ff-only`、不会 merge/rebase、不会 force push，但没有展示当前 `host:port · path`。用户在多个 SSH 工作区之间切换时，仍可能在最终确认前需要靠记忆判断目标。

## 本轮变更

- 快进拉取确认页追加当前 SSH 目标与项目路径。
- 普通推送确认页追加当前 SSH 目标与项目路径。
- 不给 fetch 增加确认弹窗：fetch 只是只读更新远端跟踪状态，保持轻量。
- 不改变 Git 行为：拉取仍只允许 `git pull --ff-only`；推送仍只允许普通非 force push；脏工作树、落后上游、游离 HEAD 等门禁保持不变。

## 主动发现记录

1. 推进：pull/push 是高风险远端同步动作，必须在最终确认前展示作用目标。
2. 暂缓：fetch 属于只读状态刷新，不加确认，避免高频只读操作变重。
3. 暂缓：后续继续检查提交、stash、文件级动作之外的其它 Git 状态变更是否也需要统一确认上下文。

## 验收点

- 推荐主按钮进入“快进拉取”时，确认页包含 `目标：host:port · path`。
- 推荐主按钮进入“普通推送”时，确认页包含 `目标：host:port · path`。
- 原有安全说明仍保留：不会 merge/rebase，不会 force push，未提交文件不会被推送。
