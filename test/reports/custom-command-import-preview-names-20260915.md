# 快捷指令导入预览可辨识验收记录

## 切片目标

让用户在手机端导入快捷指令备份前知道“将导入哪些指令”，避免只看到数量后盲确认。该能力服务于
TermuxPro 的自定义快捷指令迁移和多工作区远程开发，不触碰 Termux 原始终端能力。

## 主动发现记录

| 观察 | 来源 | 影响旅程 | 增值服务准入 | 结论 |
| --- | --- | --- | --- | --- |
| 导入确认页只展示数量、源工作区和目标工作区，不展示具体指令名称。 | 负责人代码走查 `confirmImport` | 换机/多设备迁移快捷指令 | 自定义快捷指令、移动端工作流效率 | 本轮推进 |
| 用户在导入前最关心是否导错备份，数量无法帮助区分“Codex/Git/测试/日志”等不同用途。 | 产品旅程复盘 | 从旧设备或其他工作区复制 JSON 后确认导入 | 远程工作区、自定义快捷指令 | 本轮推进 |
| 预览所有命令正文会增加弹窗长度，并可能暴露敏感路径；名称摘要更适合手机确认。 | UI/UX 与安全取舍 | 360dp/200% 字体、剪贴板导入确认 | 移动端交互体验、安全 | 本轮只显示最多 3 个名称和剩余数量 |
| 导入后按条勾选可进一步提高控制力，但会把确认弹窗升级成列表编辑器。 | Backlog 延续观察 | 大批量迁移 | 自定义快捷指令 | 暂缓，先补低成本可辨识能力 |

## 实现摘要

- 导入确认消息新增“将导入：名称1、名称2、名称3，另有 N 条”。
- 中文和英文分隔符、剩余数量文案均使用资源字符串，避免英文界面夹杂中文。
- 预览只使用已通过校验的快捷指令名称，不展示命令正文、SSH 密码、Token 或终端输出。
- 确认前仍不保存、不执行；导入后仍沿用重名后缀、秘密检测和当前工作区隔离。

## 非目标

- 不改变导入 JSON schema。
- 不增加导入列表勾选、批量编辑或云同步。
- 不执行 SSH/tmux/Git/AI CLI 命令，不改变 Termux 原始终端能力。

## 验收标准

1. 两条导入时，确认消息展示两条名称。
2. 四条导入时，确认消息只展示前三条名称和“另有 1 条”。
3. 确认前当前工作区快捷指令数量仍为 0。
4. 导入流程不启动 `TermuxActivity`，不执行远端命令。
