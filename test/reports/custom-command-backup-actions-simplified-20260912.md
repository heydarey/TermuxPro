# 快捷指令备份与迁移入口收敛回归记录（2026-09-12）

## 主动发现

本轮继续走查“手机上维护 Codex/Claude/Git/tmux 快捷指令”的旅程，候选观察如下：

1. P1，自定义快捷指令：导出和导入都是低频迁移动作，直接在页面顶部铺成两个全宽按钮，会把快捷指令页重新推向控件堆叠，违背首页和工具箱已确立的渐进展示原则。
2. P2，自定义快捷指令：空列表时“复制备份 JSON”没有实际价值，用户第一步更可能是选模板、新建或导入已有备份。
3. P2，移动端交互体验：备份/导入的安全语义相近，都属于“只处理本地配置、不执行远端命令”，合并到一个入口能减少首屏判断成本，同时仍保留显式确认。

本轮选择第 1 项推进。它不是 Termux 原始终端能力，而是 TermuxPro 自定义快捷指令的增值层信息架构优化。

## 本轮改动

- 将快捷指令页顶部的“复制备份 JSON”和“从剪贴板导入 JSON”两个常驻按钮收敛为一个“备份与迁移”入口。
- 点击“备份与迁移”后再展示二级动作：已有指令时提供复制备份和导入；空列表时只提供导入。
- 保留既有安全逻辑：复制只读本地配置，导入前确认，导入不执行远端命令，敏感命令仍被拒绝。

## 验收点

- 有效工作区下始终可发现“备份与迁移”，无效工作区隐藏。
- 空列表进入二级菜单时只出现“从剪贴板导入 JSON”，不诱导用户复制空备份。
- 已有快捷指令时二级菜单同时提供复制和导入。
- 复制/导入路径均不启动 `TermuxActivity`，不执行 SSH/tmux/Git/AI 命令。

## 后续观察

- 若备份/迁移继续扩展到工作区级配置，应继续保持“一个低频入口 + 明确二级动作”，不能把首页或快捷指令页重新堆满管理按钮。
