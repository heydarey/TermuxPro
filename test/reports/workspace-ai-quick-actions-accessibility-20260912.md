# 首页 AI 快捷启动语义验收记录（2026-09-12）

## 背景

用户高频场景是从手机 SSH 到远程服务器后使用 Claude Code 和 Codex CLI。首页的 AI 快速启动按钮为了保持小屏简洁，只显示“Claude Code / Codex CLI”，但按钮自身没有表达关键安全边界：新建会话是安全默认、历史会话必须手动选择、不会自动进入 tmux。共享 Claude 账号或多人 tmux 环境下，这会增加误以为“点一下就恢复最近上下文”的风险。

## 增值服务准入

- 分类：AI CLI、远程工作区、移动端工作流效率。
- 不是 Termux 原始能力重做：本轮不修改终端、PTY、本地 shell、包管理或基础会话行为，只增强 TermuxPro 首页 AI 增值入口的说明语义。

## 本轮改动

- 首页 Claude Code 按钮保留短文本，补充无障碍说明：打开启动确认，新建会话是安全默认，历史会话需手动选择，不自动进入 tmux。
- 首页 Codex CLI 按钮同样补充安全边界说明。
- 不改变 `claude`、`claude --resume`、`codex`、`codex resume` 的启动策略，不新增远端命令，不读取 AI 私有历史。

## 主动发现候选

1. 首页 AI 快捷启动按钮短文本简洁但安全边界不可见，可能让共享 Claude 账号误恢复上下文；本轮推进。
2. AI 启动确认弹窗已有详细说明，但用户在点击前缺少入口级提示；本轮通过 `contentDescription` 补齐，不增加首屏控件。
3. 后续还需持续观察工作台首页是否应在视觉层面增加一行极短 AI 安全提示；本轮暂缓，避免首页重新变得拥挤。

## 验收重点

- 可见按钮仍保持“Claude Code / Codex CLI”，不挤压首页。
- 两个按钮的无障碍说明必须包含“新建会话”“历史会话”和“不自动进入 tmux”。
- 原始 Termux 终端能力、远程 SSH 命令构造和 AI 启动确认流程不变。
