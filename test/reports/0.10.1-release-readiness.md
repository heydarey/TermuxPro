## 冻结范围

- AI CLI：启动历史入口、时间/工作区范围、记录管理、删除/清空确认、目标变化防误入。
- 工作区/工具箱：首页工具箱按需展开、编辑返回和空工作区删除、入口文案、tmux 策略摘要和共享账号提示。
- Git/tmux/快捷指令：Git 首屏状态摘要、提交记录上下文和筛选、项目任务验收入口、快捷指令备份导入/复制和
  导入确认、tmux 会话管理入口与归属确认。
- 终端体验：触摸滚动模式提示、终端顶栏工具箱入口说明、滑动历史/TUI 语义说明。
- 交付治理：长期分支复用、自动 PR 空差异/等待门禁/收尾 CI/候选发布流程降噪和每周发布评审规则。

## 增值服务准入

- 分类：AI CLI、远程工作区、tmux/Git 可视化、自定义快捷指令、移动端工作流效率和上下文工具箱。
- 非目标：不研究、不重写 Termux 原始终端、PTY、包管理、本地 shell、基础会话、基础快捷键或基础文件能力。
  原始 Termux 能力只做兼容守护和“不受影响”回归保护。
- 风险控制：稳定版不加入候选版之外的新功能；AI 启动固定 `ssh_only`；tmux 必须由用户显式进入或管理；
  历史会话只进入 Claude/Codex CLI 原生选择器；本地启动记录跨目标必须拦截。

## 稳定版门禁

1. `termuxpro-version.properties` 必须为 `0.10.1` / `100102`，且发布说明文件存在。
2. `versionCode=100102` 必须高于 `0.10.1-rc.1` 的 `100101`。
3. `git diff --check`、`./scripts/validate-skills.sh`、`./test/version-metadata-test.sh`、
   `./test/workflow-trigger-policy-test.sh`、`./test/release-apk-device-smoke-test.sh` 和
   `./test/release-abi-gate-test.sh` 必须通过。
4. 稳定准备分支合入 `dev` 前，分支 CI 与适用门禁必须通过，并等待合入 `dev` 后收尾 CI。
5. `dev → master` 发布 PR 的 CI 和 Emulator UI 必须通过。
6. `v0.10.1` 稳定标签必须指向 `master` 合并提交，Release workflow 必须完成签名 APK 构建、覆盖升级、
   运行时冒烟和 GitHub Release 创建。
7. 稳定 Release 必须是非草稿、非预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 稳定 Release 完成后必须将 `dev` 对齐 `master` 并等待收尾 CI。
