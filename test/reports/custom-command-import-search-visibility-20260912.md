# 快捷指令导入后筛选可见性回归

## 主动发现候选

1. **P1：导入成功但旧筛选仍生效，用户看不到导入结果。**
   - 旅程：用户在手机上筛选 `codex` 查看 AI 指令，随后从剪贴板导入一批测试/日志指令。
   - 证据：导入前筛选状态由页面持有；若导入项不匹配当前筛选，成功反馈与列表可见结果会分离。
   - 准入分类：自定义快捷指令、移动端工作流效率。
   - 推进理由：这是“迁移成功后找不到结果”的典型移动端挫败点，且修复小、风险低。
   - 非目标：不自动执行导入指令，不推送到远端，不改变原始 Termux 终端能力。

2. **P2：备份 JSON 复制后缺少下一步保存位置建议。**
   - 旅程：用户复制备份后需要自行决定保存到哪里。
   - 暂缓理由：当前反馈已说明可保存到安全位置；相比导入后不可见，优先级更低。

3. **P2：导入预览只显示数量，不列出前几条指令名称。**
   - 旅程：用户从其他设备迁移前希望快速确认内容。
   - 暂缓理由：预览内容较多可能挤压 360dp/200% 字体空间；后续可做折叠式摘要。

## 本轮改动

- 导入成功前若存在筛选词，自动清空筛选。
- 导入后反馈明确提示“已清除筛选以显示导入结果”。
- 保持安全边界：导入只写本地快捷指令配置，不执行远端命令，不启动终端会话。

## 验收点

- 当前工作区已有 4 条指令且筛选 `codex` 时，导入测试/日志指令后筛选框清空。
- 搜索统计隐藏，列表中可见新导入的“运行测试”和“查看日志”。
- 导入流程不启动 `TermuxActivity`，不执行任何 SSH/tmux/Git/AI CLI 命令。
