# 终端工具箱推荐操作验收报告（2026-09-09）

## 增值服务准入

- 分类：AI CLI、tmux/Git 可视化、自定义快捷指令、移动端工作流效率、上下文工具箱。
- 非目标：不研究、不重写 Termux 原始终端、PTY、滚动、基础会话或快捷键语义。
- 安全边界：本轮只调整终端工具箱菜单的信息架构和文案资源，不新增 SSH/tmux/Git/AI 远端命令，不改变
  任何执行路径。

## 产品问题

终端工具箱已经承载 AI、Git、tmux、项目任务、远端文件、诊断、快捷指令和键区切换，但原菜单仍按技术
类别从“当前上下文”开始排列。真实开发者在手机终端里通常先想完成高频目标：

1. 继续或新建 Claude/Codex 工作。
2. 检查 AI 修改后的 Git 状态。
3. 进入或管理指定 tmux 会话。
4. 运行自己的快捷指令。

若这些入口散落在长菜单中，用户需要记忆分类和位置，违背“工具箱按需使用、入口要直观”的方向。

## 实现

- 新增“推荐操作”分组并置顶。
- 推荐操作只包含已有安全入口：
  - AI CLI 会话中心
  - Git 状态
  - tmux 会话
  - 快捷指令
- “当前上下文”改为“当前终端”，只保留提示词、搜索输出、触摸滚动模式等与当前终端状态直接相关的操作。
- “项目与 Git”保留审查 Git Diff、远端文件、项目任务、Web 预览等二级项目操作。
- “AI 工作”保留直接启动 Claude/Codex、确认/拒绝和中断等 TUI 操作。

## 验收

- 产品验收：高频远程 AI 开发路径被前置，用户不需要理解全部工具分类后才能进入主要工作流。
- UI/UX 验收：菜单首屏先给出最可能操作，减少长列表搜索成本；分类名从抽象“当前上下文”改为更具体的
  “当前终端”。
- 架构验收：只重排菜单项，所有点击处理仍走原 `TermuxActivity` 现有分支，不新增命令注入面。
- QA 验收：`TerminalProjectToolsMenuTest` 锁定推荐分组、顺序和触摸滚动模式位置。
