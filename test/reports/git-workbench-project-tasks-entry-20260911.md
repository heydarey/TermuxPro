# Git 工作台项目任务入口验收记录（2026-09-11）

## 背景

真实使用里，AI 修改代码后通常会先看 Git 状态，再运行项目测试或构建任务完成回归。
此前 Git 工作台已经覆盖分支、改动、暂存、提交、同步和历史，但缺少从 Git 审查页直接进入
“项目任务 / 测试”的路径，用户需要退出到其他页面寻找入口。

## 本轮改动

- 在 Git 工作台概览页增加次级入口“运行项目任务 / 测试”。
- 从当前工作区打开 Git 工作台时携带 `workspaceId`，再从 Git 工作台进入项目任务页时复用同一个
  工作区归属 token。
- 对旧入口做目标一致性保护：没有 `workspaceId` 时，只有 Git 页目标与当前 active workspace 的
  host、port、path 完全一致才允许打开项目任务页；否则提示用户从“服务器与项目”重新进入，避免在
  错误服务器或目录执行任务。

## 产品验收

- 主推荐按钮仍然服务于当前 Git 状态：审查文件、提交、快进拉取、推送、分支选择等。
- “项目任务 / 测试”作为次级动作出现，不抢占 Git 主流程。
- 入口文案明确说明会先展示命令并确认，不会直接执行。
- 目标不一致时失败关闭，优先保证远程执行安全。

## 自动化验证

- `git diff --check`：通过。
- `rg` 路径检查：确认布局、字符串、导航入口和测试用例均已覆盖。
- `./scripts/resource-guard.sh`：通过，当前远程共享环境允许低资源迭代。
- `./scripts/codex-quota-guard.sh`：通过，剩余额度 62%，高于 15% 红线。

## 本机受限项

- 相关 Robolectric 单测执行前卡在 Gradle 依赖解析，`dl.google.com` 访问超时；使用国内 Maven
  开关重试后仍长时间无输出，为避免占用共享机器已中断。
- `./scripts/doctor.sh` 检测到本机 `.tooling/android-sdk` 缺少 `android.jar`、`aapt`、`adb`
  和 NDK 文件，因此本机不能作为完整 Android 验收环境。
- 完整编译、单测、lint 和模拟器 UI 验收继续交给 GitHub Actions Runner。

## 回归关注

- 从 AI CLI 中心或工作区进入 Git 工作台后，点击“运行项目任务 / 测试”应进入项目任务页。
- 从历史/旧入口打开的 Git 页面，如果与当前 active workspace 不一致，应只显示安全提示，不跳转。
- 项目任务页仍保持“先确认命令，再运行到独立 tmux 会话”的既有安全规则。
