# 工作区连接操作入口语义验收记录

## 增值服务准入

- 分类：远程工作区、移动端工作流效率。
- 结论：通过。该切片直接服务用户在手机端管理多个 SSH 工作区，不涉及重做 Termux 原始终端能力。

## 问题

用户反馈“不知道管理工作区按钮是干嘛的”。当前实现已把它从“管理工作区”改成
“复制或删除当前工作区”，但按钮实际行为是打开一个只包含复制/删除的弹出菜单，不是进入完整管理页。
这个入口仍然让用户在点击前需要猜测操作范围。

## 主动发现

| 观察 | 来源 | 影响旅程 | 优先级 | 下一动作 |
|---|---|---|---|---|
| “复制或删除当前工作区”过长，像说明句，不像可扫读的动作入口。 | UI/UX 走查 | 首页已保存连接后的首屏扫读 | P1 | 按钮短文案改为“连接操作” |
| 弹出菜单的“复制/删除”对象不明确，用户可能担心影响远端项目。 | 产品走查 | 多 SSH 工作区配置管理 | P1 | 菜单项改为“复制当前连接 / 删除当前连接” |
| 长解释应该进入无障碍与语义描述，而不是挤占按钮文本。 | QA/可访问性走查 | 大字体、屏幕阅读和误触恢复 | P1 | 给按钮补充 contentDescription，明确不影响远端文件 |

## 本轮修复

- 首页按钮文案从“复制或删除当前工作区”改为“连接操作”。
- 按钮 `contentDescription` 明确为“复制或删除当前 SSH 工作区；不会影响远端文件。”。
- 复制/删除操作项改为“复制当前连接 / 删除当前连接”，把对象从泛化“工作区”收敛到 SSH 连接配置。
- 英文资源同步调整为 `Connection actions`、`Copy connection`、`Delete connection`。

## 验收标准

1. 首页首屏按钮短、可扫读。
2. 用户点击前能从语义说明知道它只管理本地 SSH 工作区配置。
3. 删除文案不暗示会删除远端文件或项目。
4. 大字体布局继续通过现有工作区冒烟测试。
