# Git 工作台分组工具箱体验切片

## 主动发现记录

1. 候选观察：Git 工作台底部把分支、同步、stash、暂存、提交和提交记录放在横向滚动条内。
   - 证据来源：负责人走查 `activity_git_diff.xml`。
   - 影响旅程：手机用户看到“Git 工作台”后，仍需要横向扫按钮才能发现切换分支、提交记录、stash 等能力。
   - 增值服务分类：Git 可视化、远程工作区、移动端工作流效率。
   - 推进理由：直接回应“Git 功能太少/找不到”的体验问题，不触碰 Termux 原始终端能力。

2. 候选观察：已有“推荐操作”主按钮，但低频完整能力缺少结构化归类。
   - 证据来源：`GitDiffActivity.bindPrimaryAction` 与布局比对。
   - 影响旅程：用户知道下一步推荐动作，却不容易形成“分支 / 同步 / 改动 / 历史”的完整心理模型。
   - 增值服务分类：Git 可视化、移动端交互体验。
   - 推进理由：通过分组提升可发现性，比继续堆新功能更能提升当前版本可用性。

3. 候选观察：XML 片段曾出现疑似重复属性风险，需要用测试覆盖布局意图。
   - 证据来源：代码审计与精确 grep。
   - 影响旅程：布局回归若依赖人工截图才发现，会重复制造“看起来功能有，但手机上不好用”的问题。
   - 增值服务分类：移动端工作流效率、QA 门禁。
   - 推进理由：补 Robolectric 断言，确保关键入口是竖向可见的全宽按钮。

## 本轮改动

- 将 Git 工作台底部横向滚动按钮条改为竖向“Git 工具箱”。
- 工具箱按“分支管理 / 远端同步 / 改动处理 / 历史与临时保存”分组。
- 保留所有既有按钮 ID 和业务逻辑，不新增危险 Git 行为。
- 写操作仍进入原有确认弹窗；不会自动 force push、merge、rebase 或丢弃文件。
- 新增 Robolectric 测试，验证工具箱分组文案和关键全宽入口。

## 验收范围

- 已覆盖：布局资源、中文文案、Git 工作台 Robolectric 渲染与按钮可见性。
- 不覆盖：真实远端 Git 命令执行、Android 真机手势和软键盘；这些继续依赖 CI 模拟器/设备验收或用户实测反馈。

## 回归风险

- 风险：底部按钮从横向改竖向后页面更长。
- 控制：推荐主操作和当前状态仍在上方；完整工具箱属于按需继续操作，竖向滚动比横向扫按钮更符合手机阅读。
- Termux 原始能力影响：无。未修改终端 PTY、本地 shell、包管理、基础会话或快捷键。
