# Git 暂存动作目标上下文回归报告（2026-09-19）

## 背景

分支操作确认页补齐目标后，继续巡检 Git 工作台发现：`暂存全部`、`取消暂存` 和单文件暂存动作同样会改变远端仓库索引状态，但确认页只描述“不会提交/推送/丢弃”，缺少当前 `host:port · path`，多工作区场景下仍需要用户凭记忆判断目标。

## 本轮变更

- `暂存全部` 确认页追加当前 SSH 目标与项目路径。
- `取消暂存` 确认页追加当前 SSH 目标与项目路径。
- 单文件“暂存这个文件 / 取消暂存这个文件”动作菜单追加当前 SSH 目标与项目路径。
- 不改变远端命令：仍只使用既有安全暂存/取消暂存流程，不提交、不推送、不丢弃、不重置。

## 主动发现记录

1. 推进：索引状态变更是手机端高频 Git 操作，必须在最终确认前展示作用对象。
2. 暂缓：fetch/pull/push/sync 已有各自安全门禁，但仍需继续检查是否要统一目标和分支呈现。
3. 暂缓：单文件列表标题暂不增加目标，避免列表层信息密度过高；最终动作菜单已经展示目标。

## 验收点

- Robolectric 覆盖全部暂存、全部取消暂存和单文件暂存动作菜单。
- 既有文案仍明确不会提交、不会推送、不会丢弃文件。
- 深色弹窗样式继续走 `TermuxProDialogStyle`，避免黑字回退。
