# Git 分支操作目标上下文回归报告（2026-09-19）

## 背景

用户的核心场景是手机通过 SSH 进入不同服务器/项目，再使用 Codex CLI、Claude Code 和 Git/tmux 增值工具。Git 工作台已经支持分支列表、新建、切换、跟踪远端和删除本地分支，但分支状态变更确认页只解释 Git 行为，缺少当前远程目标，容易在多工作区或共享服务器场景下误操作。

## 主动发现记录

1. 推进：新建、切换、跟踪远端和删除本地分支都是会改变远端仓库状态的动作，确认页必须展示 `host:port · path`。
2. 暂缓：stage/unstage、stash、sync 等 Git 动作也需要同类巡检；本轮先处理分支链路，避免一次改动过大。
3. 暂缓：分支列表标题可考虑增加当前目标，但列表页已经有仓库概览上下文；优先级低于最终确认弹窗。

## 本轮变更

- 新增统一的 Git 确认文案包装：在原有操作说明后追加“目标：host:port · path”。
- 覆盖本地分支切换、远端跟踪分支、本地分支删除和新建分支确认页。
- 不改变任何远端 Git 命令，不新增提交、推送、拉取、重置、强制切换或远端删除能力。

## 验收点

- 多工作区场景下，用户在最终确认前能看到操作将作用到哪台服务器和哪个项目目录。
- 现有安全文案仍保留：删除本地分支不会删除远端，脏工作树切换仍被阻止。
- Robolectric 覆盖新建、切换、跟踪远端、删除本地分支四条弹窗路径。
