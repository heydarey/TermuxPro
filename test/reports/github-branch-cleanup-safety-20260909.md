# GitHub 陈旧分支清理安全门禁报告（2026-09-09）

## 背景

用户反馈 GitHub 分支数量过多，历史迭代中创建了大量一次性 `dev_*` / `hotfix_*` 分支。仓库噪声会降低
可维护性，也会让后续维护者难以判断真实活跃工作面。

## 主动发现

1. 现有 `scripts/audit-github-noise.sh` 已能排除 `master`、`dev`、`dev_dailyIteration` 和打开 PR 分支。
   - 影响旅程：仓库维护与发布治理。
   - 优先级：P1。
   - 结论：保留。
2. 脚本规则写明“删除前必须无候选/稳定发布风险”，但候选发布分支只被计数，没有从清理候选判定中提前
   排除。
   - 影响旅程：远端分支清理。
   - 优先级：P0。
   - 推进理由：如果直接依据候选清单删除，会误删发布列车分支，影响发布追溯。
3. 真实远端当前仍有 205 个分支、203 个 dev/hotfix 命名分支，确实需要后续分批清理。
   - 影响旅程：仓库专业度和长期维护。
   - 优先级：P1。
   - 暂缓理由：删除远端分支是破坏性维护，本轮先修安全门禁，下一步再基于修正后的候选清单分批执行。

## 修复

- `scripts/audit-github-noise.sh` 发现 `dev_release数字Rc数字_YYYYMMDD` 候选发布分支后，只计入候选发布
  分支数量，并立即跳过陈旧清理候选判定。
- `test/github-noise-audit-test.sh` 增加断言：候选发布分支不得出现在清理候选列表中。

## 真实复核

修复后只读审计输出：

- 远端分支总数：205
- dev/hotfix 命名分支数：203
- 保护分支数：3
- 打开 PR 分支数：0
- 候选发布分支数：20
- 已合并陈旧分支候选数：181
- 未确认或仍活跃 dev/hotfix 分支数：1
- Release 总数：40
- 稳定 Release 数：17
- Pre-release 数：23

## 下一步

- 在后续治理切片中基于 181 个候选分批清理已合并陈旧分支。
- 每批删除前再次确认：
  - 不包含 `master`、`dev`、`dev_dailyIteration`；
  - 不包含打开 PR head；
  - 不包含候选发布分支；
  - 该远端分支提交已合入 `origin/dev`。

## 验收

- `test/github-noise-audit-test.sh` 应通过。
- `scripts/audit-github-noise.sh` 的真实输出中，候选发布分支数仍可见，但不进入“已合并陈旧分支候选”。
