# 快捷指令首次创建与大字体引导审计

## 场景与发现

- 目标旅程是开发者在某个远程工作区首次打开“快捷指令”，以模板或新建方式创建一条仅属于该工作区的命令。
- 原有空态把“模板”和“新建”写成泛化按钮，首次使用者无法立即判断二者差异；安全说明与空态下一步也会在 360dp、200% 字体下占用过多首屏高度。
- 该页面的关键风险不是按钮少，而是用户误以为“选择模板”会直接运行远程命令，或不知道新建后的命令将在哪个工作区执行。

## 体验修复

1. 将入口改为明确的“选用模板 / 新建指令”，英文对应 `Use template / New command`，先表达下一步动作而非内部实现。
2. 空列表时优先呈现模板安全边界：模板只预填编辑器，保存前不会执行；已有指令时仍保留“按场景管理”这一补充说明。
3. 大于等于 150% 字体时把可见安全文案收敛为“模板只会预填编辑器；保存前不会执行。”，让操作目标和空态保留在首屏；辅助技术的 content description 继续保留完整模板范围和“不执行”边界。
4. 未改变工作区隔离、保存前不执行、危险命令确认、秘密检测或通过独立 SSH 会话执行的既有安全约束。
