# GitHub Actions 重步骤超时保护验收记录（2026-09-15）

## 背景

PR #347 首轮在文案断言修复后重新触发门禁，但 GitHub Runner 的全模块测试和模拟器截图步骤出现长时间
`in_progress`。虽然 job 级别已有 45 分钟超时，但单个重步骤缺少步骤级超时会让 PR 长时间 pending，影响自治
迭代判断，也会放大用户收到失败/等待通知的噪声。

## 本轮调整

- CI：
  - 隔离 SSH/tmux fixture 增加 5 分钟步骤级超时。
  - 全模块测试增加 20 分钟步骤级超时。
  - Lint 与 Debug APK 增加 15 分钟步骤级超时。
- Emulator UI：
  - 模拟器/系统镜像/NDK 安装、模拟器启动、设备配置、默认字体截图、200% 字体截图、Release 覆盖升级、
    证据收集和关闭模拟器均增加步骤级超时。
- 静态策略测试：
  - `test/workflow-trigger-policy-test.sh` 增加步骤级 timeout 规则，避免后续回退。

## 验收口径

- 长耗时步骤必须明确失败或成功，不允许长期无诊断 pending。
- GitHub Runner 完成最终门禁，远程共享开发机不启动本地模拟器。
- 本调整不改变产品运行逻辑，只改善自治研发流水线稳定性。
