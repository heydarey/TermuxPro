# AI 启动历史管理体验验收（2026-09-11）

## 主动发现

- 旅程：开发者在手机上频繁从同一个远程工作区启动 Claude Code / Codex CLI。
- 证据：AI CLI 会话中心最多展示最近 3 条启动，但本地按工作区最多保留 5 条；折叠记录只能通过“清空记录”
  一次性删除，不能逐条查看、重复或删除。
- 影响：用户可能看不到较早但仍有价值的启动入口，也无法只删除一条误触记录；这违反“允许产生记录就应允许
  查看和管理”的闭环原则。
- 增值服务分类：AI CLI、远程工作区、移动端工作流效率。该能力只管理 TermuxPro 本地启动记录，不读取
  Claude/Codex 私有历史，不属于 Termux 原始终端能力重做。

## 设计调整

- 在“最近 AI 启动”卡片中增加“查看全部记录”入口。
- 入口只在当前工作区存在本地记录时可用；没有有效工作区或没有记录时保持禁用。
- 弹窗展示当前工作区全部本地启动记录，用户点选后可：
  - 重复启动同一个 AI CLI 入口；
  - 删除该条 TermuxPro 本地记录。
- 删除提示明确不会删除 Claude/Codex 远端历史、tmux 会话或终端输出。

## 安全边界

- 不读取 Claude/Codex 私有历史、配置或终端输出。
- 不自动恢复最近会话；历史入口仍只打开 CLI 原生选择器。
- 不触碰 tmux 管理权限、远端文件或 SSH 凭据。

## 验收重点

- 折叠记录也能被查看和逐条管理。
- 删除单条记录后刷新摘要，不影响其他记录。
- 重复记录仍走既有 SSH-only AI 启动策略，不自动进入工作区 tmux。
- 大字体下首屏仍优先保留“新建 Claude / 新建 Codex”等安全默认操作；历史管理在记录卡片内按需使用。
