# 工作区首页动作文案清晰度验收记录

## 增值服务分类

- 远程工作区
- 移动端交互体验
- 上下文工具箱

## 主动观察

| 观察 | 来源 | 影响旅程 | 优先级 | 处理 |
|---|---|---|---|---|
| “连接操作”仍需要用户二次猜测按钮里到底有什么动作。 | 负责人/UI 走查 | 已保存工作区首页扫读 | P1 | 改为“复制/删除连接”，直接暴露对象和动作。 |
| “开发工具”像一个首页功能区标题，不像按需展开的工具箱。 | 负责人/UI 走查 | 用户展开低频工具后判断是否继续停留首页 | P1 | 卡片标题改为“开发工具箱”。 |
| 工具箱说明没有强调“按需”，容易回到首页堆控件的旧问题。 | 产品走查 | 用户判断首页和终端工具入口的边界 | P1 | 说明改为“只在需要时打开 Git、tmux、文件、项目任务、快捷指令、诊断和 Web 预览”。 |

## 实现结论

- 首页对象菜单文案从“连接操作”改为“复制/删除连接”。
- 无障碍说明从“复制或删除当前 SSH 工作区”改为“管理当前 SSH 连接的本地配置”，明确不会影响远端文件。
- 工具箱展开按钮改为“打开开发工具箱 / 收起开发工具箱”。
- 工具箱卡片标题改为“开发工具箱”，说明强调“只在需要时打开”。

## 验收重点

- 已保存工作区首页默认仍只展示连接摘要、打开远程终端、AI 快速启动和开发工具箱入口。
- 未配置或编辑连接时仍不展示工具箱，避免无目标误操作。
- “复制/删除连接”只管理本地 SSH 连接配置，不触碰远端文件。
