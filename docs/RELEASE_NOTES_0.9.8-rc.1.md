# TermuxPro 0.9.8-rc.1 候选版发布说明

`0.9.8-rc.1` 是 `0.9.7` 之后的候选体验版，冻结范围只包含 TermuxPro 增值服务改进：
AI CLI 会话中心、项目任务入口和远程执行目标上下文。本版本不研究、不重做 Termux 原始终端、PTY、
包管理、本地 shell、基础会话、基础快捷键或基础文件能力；这些能力只作为“不被增值层破坏”的兼容回归面。

## 主要变化

- AI CLI 会话中心的“AI 完成后”阶段新增“运行项目任务”入口。开发者可以从 AI 结果检查路径直接进入
  项目任务/测试页，不需要把验证命令手动输入到正在工作的 Claude/Codex TUI 里。
- 项目任务页新增“执行目标 · host:port · path”上下文，并支持复制核对。多工作区和共享服务器场景下，
  用户在运行测试、构建或开发脚本前可以明确确认任务会在哪个远端目标执行。
- 项目任务错误态也保留执行目标展示，避免只看到失败提示但无法判断失败发生在哪台服务器或哪个目录。

## 验收重点

1. 候选 APK 必须完成 `0.9.7 → 0.9.8-rc.1` 覆盖升级验收。
2. AI CLI 会话中心不得读取 Claude/Codex 私有历史，不得自动进入 tmux。
3. AI 快捷启动仍必须使用独立 SSH-only 终端，不继承工作区自动 tmux 策略。
4. 项目任务入口必须复用结构化项目任务页，不得向当前 Claude/Codex TUI 直接注入命令。
5. 项目任务页必须显示执行目标；无效工作区必须失败关闭并回退到工作台。
6. 360dp、深色主题、默认字体和 200% 字体下，新增入口和执行目标必须可读、可点击。
7. Release 必须是非草稿、预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 原始 Termux 终端、PTY、本地 shell、基础会话和基础快捷键语义不得被 TermuxPro 增值层修改。

## 已知限制

- 本版本仍不读取 Claude/Codex 内部历史文件；历史列表由 CLI 原生选择器负责。
- 项目任务仍以自动识别的 Node/Maven/Gradle 常用任务为主，自定义任务编排继续由快捷指令模板承载。
- 本地共享服务器 KVM 不可用，候选 APK 的覆盖升级与截图验收依赖 GitHub Runner 模拟器。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.7` 正式版，可直接覆盖升级到本候选版本。
