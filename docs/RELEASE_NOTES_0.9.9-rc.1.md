# TermuxPro 0.9.9-rc.1 候选版发布说明

`0.9.9-rc.1` 是 `0.9.8-rc.1` 之后的新候选体验版。由于 `0.9.8-rc.1` 后继续合入了终端滚动提示、
Git 工作台和快捷指令等用户可见体验切片，本版本不复用 `0.9.8` 发布列车，而是以新的候选版本冻结这批
增值服务改进。

本版本仍只打磨 TermuxPro 增值层：SSH 远程开发、Codex CLI / Claude Code 工作流、Git/tmux 可视化、
自定义快捷指令和移动端交互体验；Termux 原始终端、PTY、本地 shell、包管理、基础会话和基础快捷键只做
兼容回归，不作为重复研发对象。

## 主要变化

- 终端触摸滚动模式入口更清楚：终端顶栏和工具箱会明确当前手势语义，区分“滑动看历史”和“滑动控制
  AI/TUI 面板”，降低用户误判滚动失效的概率。
- Git 工作台首屏展示最近 3 条提交摘要，让用户在手机上直接判断当前分支最近发生了什么，不必先进入
  二级提交记录。
- 自定义快捷指令按 Git、tmux、AI CLI、测试、发布等场景分组展示，并补充场景说明，减少把快捷指令
  理解成孤立按钮的成本。
- Git 工作台首屏新增“下一步建议”卡片：根据游离 HEAD、未提交、已暂存、无上游、领先/落后和干净同步
  状态提示最安全的下一步。

## 验收重点

1. 候选 APK 必须完成 `0.9.7 → 0.9.9-rc.1` 覆盖升级验收。
2. 终端触摸滑动默认可查看历史输出；切到 AI/TUI 面板模式后文案必须明确行为变化。
3. Git 工作台必须展示当前目标、分支、同步状态、最近提交和下一步建议。
4. Git 下一步建议不得执行隐式写操作；无上游不得猜目标分支，拉取不得自动 merge/rebase，推送不得
   force push。
5. 自定义快捷指令必须按场景分组，但不得改变用户保存顺序和执行安全门禁。
6. 360dp、深色主题、默认字体和 200% 字体下，终端工具箱、Git 工作台和快捷指令页面必须可读、可点击。
7. Release 必须是非草稿、预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 原始 Termux 终端、PTY、本地 shell、基础会话和基础快捷键语义不得被 TermuxPro 增值层修改。

## 已知限制

- 本版本仍不读取 Claude/Codex 内部历史文件；历史选择继续交给 CLI 原生选择器。
- Git 工作台仍保持安全优先：不提供 force push、硬重置、自动 rebase/merge 或删除远端分支。
- 自定义快捷指令暂不做云同步或公共模板市场。
- 本地共享服务器 KVM 不可用，候选 APK 的覆盖升级与截图验收依赖 GitHub Runner 隔离模拟器。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.7` 正式版或 `0.9.8-rc.1` 候选版，可直接覆盖升级到本候选版本。
