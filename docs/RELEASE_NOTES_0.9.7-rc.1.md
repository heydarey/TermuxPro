# TermuxPro 0.9.7-rc.1 候选版发布说明

`0.9.7-rc.1` 是 `0.9.6` 之后的候选体验版，冻结范围只包含 TermuxPro 增值服务改进：
AI CLI 启动前环境预检、工作区 tmux 策略可见化，以及 AI 会话中心行动分组。

本版本不研究、不重做 Termux 原始终端、PTY、包管理、本地 shell、基础会话、基础快捷键或基础文件能力；
这些能力仅作为“不被增值层破坏”的兼容回归面。

## 主要变化

- AI CLI 会话中心新增“检查 AI 远端环境”：启动 Claude Code 或 Codex CLI 前，可进入只读诊断页确认
  项目路径、tmux、Git、Node/Java、Claude 和 Codex 是否可用。
- AI 会话中心展示工作区连接策略与 AI 快捷启动策略的差异：工作区可配置普通 SSH、只列 tmux、进入指定
  tmux、创建或进入指定 tmux；但 Claude/Codex 快捷启动始终只建立 SSH，不继承自动 tmux 策略。
- 页面信息架构调整为“当前上下文 → 启动前先确认 → 启动 AI → AI 完成后”，把环境预检、tmux 会话管理、
  Git 检查、快捷指令和服务器配置放到对应阶段，减少按钮堆叠和理解成本。

## 验收重点

1. AI 环境预检只能执行只读诊断，不能读取 Claude/Codex 私有历史，不能自动进入或创建 tmux。
2. AI 快捷启动 Claude/Codex 时必须打开独立 SSH-only 新终端；即使工作区配置了自动 tmux，也不能继承。
3. 共享 Claude 账号场景下，历史入口只能进入 CLI 原生选择器，不能自动续接最近会话。
4. 启动前阶段应能直达连接诊断和 tmux 会话中心；AI 完成后阶段应能直达 Git 工作台、快捷指令和工作区配置。
5. 360dp、深色主题、默认字体和 200% 字体下，AI 会话中心关键文案和入口必须可读、可点击。
6. 原始 Termux 终端、PTY、本地 shell、基础会话和基础快捷键语义不得被 TermuxPro 增值层修改。

## 已知限制

- 本候选版仍不读取 Claude/Codex 内部历史文件；历史列表由 CLI 原生选择器负责。
- AI 环境预检只判断远端工具是否可用，不替用户登录 Claude/Codex，也不自动批准任何 AI CLI 权限。
- 本地共享服务器 KVM 不可用，候选 APK 的覆盖升级与截图验收依赖 GitHub Runner 模拟器。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.6` 正式版，可直接覆盖升级到本候选版本。
