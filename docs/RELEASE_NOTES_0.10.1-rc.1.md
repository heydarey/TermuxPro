# TermuxPro 0.10.1-rc.1 候选版发布说明

`0.10.1-rc.1` 冻结 `0.10.0` 正式版之后的一周日常迭代成果。本版本继续只打磨
TermuxPro 增值层：SSH 远程开发、Claude Code / Codex CLI 使用体验、tmux/Git 可视化管理、自定义快捷
指令、移动端工具箱和发布交付质量；Termux 原始终端、PTY、本地 shell、包管理、基础会话和基础快捷键只做
兼容守护，不作为差异化功能重做。

## 主要变化

- AI CLI 启动历史继续补齐闭环：可展示时间、工作区范围、管理全部记录、删除/清空前确认，并阻止旧启动记录
  在工作区目标变化后误入新的服务器或目录。
- 工作区和终端入口继续降噪：工具箱改为按需展开，终端顶栏和首页文案更明确，编辑/删除/返回等路径补齐闭环。
- Git 增值能力继续加强：工作台展示首屏状态摘要、提交记录上下文、本地筛选、推荐后续操作和项目任务验收入口，
  帮助手机上判断 AI 修改后下一步该做什么。
- 自定义快捷指令继续完善：支持备份复制、备份导入、导入目标确认、行级操作对象说明和 Codex 新建模板。
- tmux/AI/共享账号安全提示继续收敛：明确会话管理入口、非当前归属会话进入前确认、AI 快捷启动不自动继承
  工作区 tmux 策略。
- 终端触摸滚动语义继续补强：入口文案和状态提示明确当前是“滑动看历史”还是“滑动控 TUI”，避免把触摸滑动
  误转成命令行上下键。
- 发布与仓库治理继续降噪：长期复用 `dev_dailyIteration`，自动 PR 等待最新 UI 影响提交的模拟器门禁，减少
  空差异、误等待和失败邮件噪声；本周发布节奏改为“克制但不断档”。

## 验收重点

1. 候选 APK 必须完成 `0.10.0 → 0.10.1-rc.1` 覆盖升级验收。
2. Claude Code / Codex CLI 快捷启动必须始终只建立 SSH，不自动进入 tmux、不自动恢复旧历史、不读取 CLI 私有历史。
3. AI 启动历史在工作区目标变化后必须阻止“一键重复”，并给出清晰可取消的说明。
4. 首页、终端顶栏、工作台、AI 会话中心、Git 工具、tmux 工具和快捷指令入口在深色主题、360dp、默认字体和
   200% 字体下必须保持可读、可返回、可取消。
5. Git/tmux/快捷指令相关入口必须遵守 CRUD 和危险操作确认原则，不提供 force push、硬重置、静默删除或
   自动污染当前 shell 的能力。
6. 自动 PR、CI 和 Release 工作流不得把普通治理变更误判为需要重复模拟器或重复候选包。
7. Release 必须是非草稿、预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 原始 Termux 终端、PTY、本地 shell、包管理、基础会话、基础快捷键和基础滚动语义不得被 TermuxPro 增值层破坏。

## 已知限制

- 本版本仍不读取 Claude/Codex 内部历史文件；历史选择继续交给 CLI 原生选择器，TermuxPro 只记录自身发起的
  安全启动记录。
- Git 工作台仍保持安全优先：不提供 force push、硬重置、自动 rebase/merge 或删除远端分支。
- 本地共享服务器 KVM 不可用，候选 APK 的覆盖升级与截图验收依赖 GitHub Runner 隔离模拟器；涉及厂商 ROM
  输入法、锁屏后台或弱网行为时仍需后续真机/云真机样本。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.10.0` 正式版，可直接覆盖升级到本候选版本。
