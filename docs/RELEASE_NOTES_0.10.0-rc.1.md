# TermuxPro 0.10.0-rc.1 候选版发布说明

`0.10.0-rc.1` 冻结 `0.9.9-rc.1` 之后的远程开发体验改进。本版本继续只打磨 TermuxPro 增值层：
SSH 远程开发、Claude Code / Codex CLI 使用体验、tmux/Git 可视化管理、自定义快捷指令和移动端交互；
Termux 原始终端、PTY、本地 shell、包管理、基础会话和基础快捷键只做兼容回归。

## 主要变化

- AI CLI 会话中心继续优化 200% 字体和窄屏层级：四个核心入口“新建/历史 Claude、Codex”保持首屏可扫读。
- tmux 会话中心在大字体下优先展示当前工作区和可操作会话，其他归属只读管理，降低共享账号误操作风险。
- 工作区首页把抽象“高级设置”改为“tmux 连接方式”，展开后直接说明连接后是否进入 tmux、默认会话名和共享账号风险。
- Git 提交前确认框新增当前分支与 `host:port · path`，避免多服务器/多项目场景下误提交。
- AI 启动前新增风险摘要：点击 Claude/Codex 前即可看到本次启动只建立 SSH，不自动进入 tmux 或恢复历史；若工作区配置了默认 tmux，也明确不会被 AI 快捷启动继承。
- 自动研发 PR 的 Actions 可见步骤改为“创建 PR、等待门禁、合并并验证 dev”，并写入 Step Summary，降低对等待状态/失败邮件的误判。

## 验收重点

1. 候选 APK 必须完成 `0.9.7 → 0.10.0-rc.1` 覆盖升级验收。
2. AI 会话中心在 360dp、深色主题、默认字体和 200% 字体下必须可读，核心启动入口不能被低优先级说明挤出首屏。
3. Claude/Codex 快捷启动必须始终只建立 SSH，不自动进入 tmux、不自动恢复历史、不读取 AI 私有历史。
4. 工作区配置为自动进入 tmux 时，AI 会话中心必须在点击前解释该策略不会被 AI 启动继承。
5. Git 提交确认必须展示当前分支和远程目标，且只提交已暂存内容，不推送、不自动暂存、不丢弃工作区文件。
6. 自动 PR 工作流的 GitHub 可见步骤必须说明等待 CI、模拟器和 dev 收尾，不再误导为创建 PR 卡死。
7. Release 必须是非草稿、预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 原始 Termux 终端、PTY、本地 shell、基础会话和基础快捷键语义不得被 TermuxPro 增值层修改。

## 已知限制

- 本版本仍不读取 Claude/Codex 内部历史文件；历史选择继续交给 CLI 原生选择器。
- Git 工作台仍保持安全优先：不提供 force push、硬重置、自动 rebase/merge 或删除远端分支。
- 本地共享服务器 KVM 不可用，候选 APK 的覆盖升级与截图验收依赖 GitHub Runner 隔离模拟器。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.7` 正式版或 `0.9.9-rc.1` 候选版，可直接覆盖升级到本候选版本。
